## 🛡️ سجل التحسينات والإصلاحات الأمنية (Changelog v21)

### 1. إغلاق ثغرة تسريب بيانات الطلبات (`api/orders.js`):
- **نظام المصادقة المزدوج (Dual Auth Guard):** تم تفعيل نظام تحقق أمني ثنائي يتطلب إما مفتاح داخلي آمن (`x-api-key: ZALO_INTERNAL_API_KEY`) أو رمز جلسة صالح وموقع من Supabase Auth (`Authorization: Bearer <token>`).
- **التحكم بالوصول المبني على الأدوار (RBAC):** لا يمكن لأي مستخدم استعراض أي طلبات إلا إذا كان صاحب الطلب (`customer_id` أو `customerName`)، أو التاجر المالك للمتجر المعني، أو مشرفاً/مديراً مصرحاً له (`ADMIN` / `SUPER_ADMIN`).
- **حماية CORS الديناميكية:** تقييد الوصول للأصول والنطاقات المعتمدة لمنع طلبات Cross-Origin غير المصرح بها.

### 2. تأمين وعزل مفاتيح الذكاء الاصطناعي (Gemini AI Proxy):
- **إزالة المفاتيح من ملفات العميل:** تم إزالة مفاتيح Gemini API من ملفات الواجهة والـ APK نهائياً.
- **بوابة الخادم الخلفي (`GeminiController`):** استقبال طلبات الذكاء الاصطناعي عبر مسار محمي في NestJS (`/api/gemini/chat`) يعتمد حصراً على `process.env.GEMINI_API_KEY` مع معالجة الأخطاء الصارمة (500 Error عند غياب المفتاح).

### 3. إصلاحات تكامل قاعدة البيانات والمصادقة (PostgreSQL & NestJS):
- **إصلاح جدول الجلسات (`public.sessions`):** إلغاء قيد `NOT NULL` عن حقل `expires_at` وتعيين قيمة افتراضية تلقائية مدتها 30 يوماً (`NOW() + INTERVAL '30 days'`).
- **ربط المفاتيح الأجنبية الصحيحة:** تعديل `auth.service.ts` لربط الجلسات بالمعرف الرقمي المتسلسل للمستخدم (`users.id` من نوع Integer) بدلاً من الـ UUID المباشر لمنع أخطاء قيود المفاتيح الخارجية.
- **تحديث سياسات الـ RLS للمتاجر والمنتجات:** السماح برؤية المتاجر بحالة `approved` أو `active` وتجاهل حالة الأحرف (`ILIKE`) مع منح التاجر حق الوصول لمتجره بربط `supabase_uid = auth.uid()`.

### 4. تنظيف وهيكلة المستودع البرمجي:
- أرشفة الملفات والأدوات المؤقتة داخل مجلد `tools/archive/` للحفاظ على نظافة جذر المشروع واستقراره.

## ⚙️ المتطلبات الأساسية (Prerequisites) — للاستخدام الداخلي فقط
لتشغيل هذا المشروع بنجاح، يجب توفير المكونات التالية (تُمنح فقط للفريق الداخلي المعتمد):
- **Node.js** (v20 أو أعلى)
- **PostgreSQL** (v15 أو أعلى)
- **Android Studio** (لمطوري التطبيق)
- **ملف `.env`** مُوقّع من الإدارة (يحتوي على مفاتيح JWT، قاعدة البيانات، وبوابات الدفع). هذا الملف لا يُرفع إلى المستودع العام.

## 🚀 خطوات التثبيت (للفريق الداخلي فقط)
*ملاحظة أمنية هامة: لا يمكن تشغيل المشروع دون الحصول على مفاتيح البيئة من فريق DevSecOps عبر قناة آمنة.*

1. استنساخ المستودع (بإذن مسبق).
2. تثبيت تبعيات الباك-إند وتشغيله:
   ```bash
   cd backend
   npm install
   npm run start:dev
   ```

3. تثبيت تبعيات الواجهة الأمامية (اختياري لتشغيل الاختبارات):
   ```bash
   cd ../web
   npm install
   ```
4. إعداد قاعدة البيانات المحلية:
   ```bash
   psql -U postgres -d zalo_db -f database/schema.sql
   ```
5. فتح الويب: استخدام Live Server لتشغيل web/index.html.
6. بناء الأندرويد: يتطلب توقيع إصدار بمفاتيح موقعة من قبل الإدارة.
